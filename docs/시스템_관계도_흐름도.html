3. 데몬 워커란 무엇인가 — 부하도 보조도 아니다

네 워커 사이에 계급은 없다 — 다른 것은 '앉은 자리'뿐. 네 워커 모두 같은 작업 폴더에서 파일을 읽고 쓰고 명령을 실행한다 — 능력은 대등하다. 차이는 창이 있고 대화가 이어지느냐(Claude Code), 부를 때 일어나느냐(데몬)뿐이다. 
 데몬 워커는 두 가지 모드로 일한다.

 ┌─ 【독립 실행】 ─────────────────────────────────────────────┐
 │  폰의 Codex 탭 / Antigravity 탭 / Grok 탭 → 직접 지시 → 완결  │
 │  Claude Code는 이 일이 있었는지도 모른다                             │
 │  → 이때 데몬 워커는 독립 작업자                                │
 └───────────────────────────────────────────────────────────┘

 ┌─ 【위임 수행】 ─────────────────────────────────────────────┐
 │  Claude Code → delegate.js 호출 → 결과를 Claude Code가 받아 이어간다        │
 │  → 이때만 보조 성격을 띤다                                │
 └───────────────────────────────────────────────────────────┘

 같은 워커가 상황에 따라 성격이 바뀐다.
 그래서 '보조'로 못 박으면 틀리고, '부하'는 더더욱 아니다.
부르는 말적절한가이유
부하✘지시 관계가 고정돼 있지 않다. 사용자가 직접 부리는 일이 더 많다
보조✘독립 실행할 때는 보조가 아니라 주역이다
데몬 워커✔부를 때 일어난다는 뜻일 뿐 — 역할은 상황마다 다르다
 데몬 워커에게 일을 시키는 세 가지 길 — 셋 다 같은 워커에게 간다

 ① 폰 → 해당 탭에서 직접 지시      Claude Code를 거치지 않음 · 가장 빠름
 ② PC 터미널에서 직접              codex exec "지시"  /  agy -p "지시"  /  grok -p "지시" -m grok-4.6 --always-approve
 ③ Claude Code에게 시키기                 node delegate.js codex "지시"

 ①이 나은 때 — 단순 작업, 빠른 답, Claude Code가 바쁠 때 동시 진행
 ③이 나은 때 — Claude Code가 결과를 받아 이어서 판단해야 할 때, 여러 워커를 엮을 때
⚠️ 같은 파일을 동시에 만지면 안 된다. 데몬 워커도 파일을 쓴다(실측 확인). 두 워커가 같은 파일을 동시에 고치면 나중에 저장한 쪽이 이기고 되돌릴 수단이 없다. 2026-09-17 에 server.js 에서 실제로 작업이 두 번 사라졌다.
→ 서로 다른 파일이면 동시에 시켜도 좋다(오히려 빠르다). 같은 파일이면 Claude Code를 거쳐 순서를 잡을 것.

10. 반드시 지킬 것

PC에 Claude Code 창은 한 개만. 여러 개면 가장 최근 창으로 지시가 들어갑니다.
브라우저 터미널·별도 세션·node-pty 는 쓰지 않습니다 (2026-09-17 폐기).
시행착오 기록 — PC 창 연결을 ① 헤드리스 별도 세션 ② 브라우저 공유 터미널(PTY) 로 만들었다가 둘 다 폐기했습니다. 둘 다 “폰 = PC 창 그대로” 라는 원칙을 깼기 때문입니다. 정답은 PC 창의 콘솔 입력 버퍼에 직접 타이핑하는 것이었습니다.
